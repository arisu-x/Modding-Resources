# Category Guide

Use this guide to decide where a resource belongs and to help keep the index easy to scan.

| Category | Include | Avoid |
|---|---|---|
| Android reverse engineering | APK, DEX, resources, smali, manifest, signing tools | Generic web tools with no Android use |
| Dynamic instrumentation and hooking | Runtime tracing, Java/ART hooks, native hooks | Cheats or unauthorized bypass guides |
| Root and system modification | Root frameworks, modules, device-level tooling | Instructions intended to defeat device ownership controls |
| Native and binary analysis | Disassemblers, debuggers, emulators, ELF/PE/Mach-O tooling | Malware samples or exploit payloads |
| Networking and protocol analysis | Packet capture, proxies, HTTP/RPC, protocol formats | Credential theft or traffic interception without authorization |
| Malware analysis | Sandboxes, detection rules, isolated lab tooling, threat intelligence | Live malware distribution or operational abuse |
| Cryptography and data formats | Encoders, hash auditing, parsers, metadata tools | Guidance for breaking into real accounts |
| Automation and scripting | SDKs, automation libraries, analysis scripts, emulators | Unreviewed scripts presented as safe by default |
| Developer and workflow tools | Git, containers, editors, task runners, CI tooling | Product lists unrelated to engineering |
| Game modding | Official SDKs, loaders, plugin frameworks, engine docs | Multiplayer cheats, DRM circumvention, copyrighted asset redistribution |
| Learning resources | Courses, documentation, labs, CTFs, books, references | Paid promotions without educational value |

## Entry quality checklist

A good entry has:

- A stable official project, documentation, or repository URL.
- A short factual description explaining why it is useful.
- A clear category and, when helpful, an open-source/commercial or active/reference label.
- No exaggerated claims, affiliate links, malware, credential theft, or unauthorized bypass instructions.
- Enough maintenance context to identify abandoned projects honestly.

Prefer one strong canonical link over several mirrors. If a project is archived, say so rather than silently presenting it as current.
