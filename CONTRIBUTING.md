# Contributing

Thanks for helping keep Modding-Resources useful and current.

## Add or update a resource

1. Check that the resource is not already listed.
2. Use the canonical official website or source repository.
3. Put it in the narrowest relevant category.
4. Use a neutral one-sentence description focused on what it does.
5. Mark a project as archived or reference-only when appropriate.
6. Check links and Markdown locally before opening a pull request.

Use this format in tables:

```md
| [Project](https://canonical.example/) | Short, factual description of its primary use. |
```

## Review standards

A contribution should be:

- Relevant to modding, reverse engineering, security research, development, or learning.
- Legal and authorized-use focused.
- Useful to a reader who has not seen the project before.
- Free from promotional claims, affiliate links, malware, credential theft, multiplayer cheats, or DRM-circumvention instructions.
- Clear about whether it is open source, commercial, archived, or experimental.

## Pull request checklist

- [ ] The link is canonical and works.
- [ ] The resource is not duplicated.
- [ ] The category is appropriate.
- [ ] The description is concise and factual.
- [ ] The change does not expose secrets or private data.
- [ ] Markdown formatting and table pipes render correctly.
- [ ] Any safety or licensing limitations are documented.

For large additions, explain the user problem being solved and why the proposed category is the best fit.
